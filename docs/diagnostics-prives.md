# Diagnostics privés — backend 0.16.3

Le collecteur existant est renforcé ; aucune table ni migration supplémentaire. Les erreurs client restent dans `client_error_events`, les liens explicitement créés par un MJ dans `diagnostic_shares` avec empreinte du jeton et expiration de 24 heures.

- Envoi : session authentifiée, politique de version exacte, lot de 20 événements au plus, environ 200 événements par compte et minute. Un ACK liste uniquement les identifiants persistés ou déjà présents. La reprise utilise le même identifiant, avec unicité par compte.
- Consultation/partage : rôle permanent MJ **et** mode effectif MJ. Un MJ connecté en Joueur reste refusé. Aucun accès agent permanent ni compte de maintenance créé ; le diagnostic passe par les accès MJ autorisés ou un lien explicitement partagé, à garder privé.
- Contenu : champs techniques autorisés seulement ; corps de requêtes, en-têtes, fiches, conversations et objets de comptes exclus. Rôle et version sont réattribués par le serveur. Les chaînes sont bornées et expurgées des secrets reconnaissables, URLs, chemins privés et textes cités. Aucun filtre de texte ne peut reconnaître toute donnée personnelle arbitrairement incluse dans une erreur : ne jamais construire une erreur à partir d'un contenu privé.
- Les avertissements PHP, erreurs HTTP et exceptions produisent également des événements techniques sans message PHP brut, argument, SQL ou configuration. Le dossier est déduit du **chemin**, sans lire le secret, de la configuration privée : `regie-private/diagnostics`, jamais la racine publique `regie`. Une configuration qui pointe dans la racine publique est refusée pour le journal.
- Journal PHP : fichiers quotidiens `server-YYYY-MM-DD.ndjson`, dossier 0700/fichiers 0600 sur un hôte compatible ; au plus cinq événements par requête et 8 Mio par jour. Aucun effacement de journaux historiques. La consultation est bornée aux sept derniers jours, aux 256 Kio finaux de chaque fichier et à 500 événements. La lecture est ajoutée sous `serverErrors` au journal MJ et à son partage explicite.

Le journal PHP ne dépend pas de MySQL pour écrire. Si la base ou l'authentification est indisponible, sa consultation API peut toutefois rester indisponible jusqu'au rétablissement. Si le dossier privé est inaccessible, un disque plein, une concurrence de verrou ou la capacité quotidienne empêche l'écriture, le collecteur n'interrompt pas la requête métier ; une notification technique générique est laissée au journal PHP disponible. Les erreurs de parsing avant l'installation des gestionnaires, la mort du processus, les coupures et OOM ne permettent pas une garantie absolue de capture.

Preuves attendues : contrats PHP natifs `diagnostics-contract.php` (droits, déduplication, filtrage et partage) et `runtime-diagnostics-contract.php` (écriture privée indépendante de la base). Ils utilisent des données synthétiques et une doublure PDO : ce n'est ni une recette MySQL/OVH réelle, ni la preuve d'un déploiement. Les permissions et la réception centrale réelle doivent être observées après le basculement OVH autorisé. Aucune exportation ou restauration SQL n'est nécessaire à cette évolution.
